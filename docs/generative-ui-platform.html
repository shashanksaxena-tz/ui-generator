01 — The Two Repos

How They Differ

Syntux

★ 15 · v0.1.0 · puffinsoft
Layout composition engine — "arrange my components smartly"
  • Generates a React Interface Schema (AST) from your component palette + data
  • LLM never sees source code — only auto-generated docs (llmContext via Babel)
  • Output is cacheable & reusable with different data values
  • Stateless by design — no dynamic state generation
  • Works with allowedComponents constraint — enforces design consistency
  • Uses Vercel AI SDK for LLM provider abstraction
  • Lightweight: compose once, hydrate many times

Tambo

★ 9.1k · v1.0 · tambo-ai · SOC 2 + HIPAA
Full-stack agent runtime — "pick, stream, render, interact"
  • Agent included — runs the full LLM conversation loop for you
  • Component registration via Zod schemas → become LLM tool definitions
  • Streaming props in real-time as LLM generates them
  • Generative + Interactable components (persist & refine via conversation)
  • Built-in MCP support (tools, prompts, elicitations, sampling)
  • Local browser-side tools (DOM, authenticated fetches, React state)
  • Self-hostable (Docker) or Tambo Cloud hosted backend
  • Multi-LLM: OpenAI, Anthropic, Gemini, Mistral, any OpenAI-compatible

05 — Theming Intelligence

Yes, Theming Can Be Built In

Multiple MCP servers already handle theming. The pipeline: user provides a brand color (or even just a logo/screenshot) → the theme MCP generates a full design token system → Tailwind CSS v4 @theme variables propagate to every component → Syntux and Tambo render everything consistently.

01
Brand Input

User provides one brand color, a Figma file, or says "modern dark SaaS theme." Agent routes to theme MCP.

Flowbite MCP Tailwind Gemini Figma MCP
02
Token Generation

MCP generates full palette (9 shades), typography scale, spacing tokens, border radii, shadows. Outputs as Tailwind @theme CSS variables or config.

@theme { --color-* } CSS custom properties Dark mode variants
03
Propagation

Tailwind v4 makes tokens available as CSS variables AND utility classes. Every component from every MCP server inherits the theme automatically. Syntux layouts and Tambo-rendered components all stay consistent.

bg-primary-500 var(--color-primary) Runtime swappable
06 — Growth Ceiling & Realistic Limits

Where This Tops Out

🟢 What Works Today

  • Single-shot dashboards, forms, data viz, landing pages
  • Multi-component page composition with cached layouts
  • Real-time streaming of component props as LLM generates
  • MCP integration for data (Linear, Slack, databases)
  • Interactable components that persist & refine conversationally
  • Brand color → full theme pipeline via existing MCP servers
  • Dark/light mode switching via CSS variables at runtime
  • Component selection from 25+ libraries via MCP
  • Self-hostable end-to-end (Tambo Docker + MCP servers)

🟡 Current Limits & Growth Areas

  • Syntux is v0.1.0 — no stateful generation, no complex interactivity in layouts
  • Cross-MCP component mixing can have style conflicts (no universal adapter yet)
  • Complex multi-page apps still need manual wiring between generated pages
  • Real-time collaboration (multi-user on same generated UI) is not yet solved
  • LLM quality ceiling — very complex layouts may need 2-3 refinement turns
  • Theme MCP servers don't yet auto-detect existing design systems
  • No unified "component marketplace" protocol — each MCP has its own API shape
  • Animations/transitions between generated components are inconsistent
